# 📚 Бот книжкових новин для Telegram

Бот сам збирає читацькі новини з RSS-стрічок книжкових медіа: нові книжки, анонси видавництв, премії, фестивалі. Він відкидає рекламу й повтори, оформлює кожну новину в пост з обкладинкою та хештегами і за розкладом публікує її у вашому каналі.

```
📚 Видавництво Старого Лева анонсувало новий роман Сергія Жадана

Новинка вийде друком у грудні. Передпродаж уже відкрито.

👉 Читати повністю · Читомо
#новинки #Читомо
```

## Що вміє

- **Збір новин** з будь-яких RSS/Atom-стрічок. Якщо дати адресу сайту, бот сам знайде на ньому RSS.
- **Картинки**: з RSS-стрічки, а якщо там немає, то головне зображення зі сторінки статті (og:image).
- **Фільтри**: слова «тільки про» та стоп-слова, окремі для кожного джерела й спільні для всіх.
- **Без дублів**: однакову новину з кількох джерел бот публікує лише раз.
- **Автохештеги** `#новинки`, `#премії`, `#переклади`, `#дитячі_книжки` тощо. Правила задаються в `sources.yaml`.
- **Розклад**: мінімальний проміжок між постами, тихі години вночі, ліміт постів на добу.
- **Модерація** (за бажанням): кожна новина спершу приходить адмінам із кнопками
  «✅ Опублікувати зараз», «🕒 У чергу», «❌ Пропустити».
- **Керування з Telegram**: додати чи вимкнути джерело, поставити на паузу, опублікувати пост негайно.
- Старі новини не публікуються, тож після перерви канал не засиплють торішні пости.

## Найпростіший запуск: прямо на GitHub (безкоштовно, без сервера)

Бот уже налаштований працювати через GitHub Actions. Кожні 30 хвилин він збирає новини й публікує один пост. Базу він зберігає в гілці `bot-state`.

1. Додайте бота адміністратором каналу з правом «Публікувати повідомлення».
2. У репозиторії відкрийте **Settings → Secrets and variables → Actions → New repository secret** і створіть:
   - `BOT_TOKEN` — токен від @BotFather;
   - `CHANNEL_ID` — `@назва_каналу` або числовий id `-100…`;
   - `ADMIN_IDS` (необов'язково) — ваш Telegram ID. На нього бот надсилатиме попередження, наприклад якщо втратить доступ до каналу.
3. Відкрийте вкладку **Actions** → «Книжкові новини» → **Run workflow**, щоб перший раз запустити бота вручну. Далі він працюватиме сам.

Налаштування змінюються на тій самій сторінці, у вкладці **Variables**: `POST_INTERVAL_MIN`, `QUIET_HOURS`, `MAX_POSTS_PER_DAY`, `POST_SIGNATURE`, `PAGE_IMAGES`. Джерела задаються у файлі `sources.yaml`, який можна редагувати прямо на GitHub.

Обмеження цього режиму:
- команди в Telegram (`/status`, `/add`…) і модерація кнопками не працюють, бо бот не запущений постійно; новини публікуються автоматично;
- GitHub може запускати бота із запізненням на кілька хвилин;
- якщо в репозиторії 60 днів не було змін, GitHub вимикає запуски за розкладом. Тоді у вкладці Actions з'явиться кнопка, щоб увімкнути їх знову.

Щоб працювали команди й модерація, запустіть бота на сервері чи комп'ютері (див. нижче).

## Запуск на сервері або комп'ютері за 5 кроків

### 1. Створіть бота
Напишіть [@BotFather](https://t.me/BotFather) → `/newbot` → придумайте ім'я. Скопіюйте **токен**.

### 2. Додайте бота в канал
Відкрийте налаштування каналу → «Адміністратори» → «Додати адміністратора». Знайдіть свого бота й залиште йому право **«Публікувати повідомлення»**.

### 3. Налаштуйте `.env`
```bash
cp .env.example .env
```
Впишіть у файл щонайменше три рядки:
```
BOT_TOKEN=токен_від_BotFather
CHANNEL_ID=@назва_вашого_каналу
ADMIN_IDS=ваш_telegram_id
```
> Свій Telegram ID можна дізнатися так: запустіть бота, напишіть йому `/start`, і він покаже ID. Потім впишіть ID в `.env` і перезапустіть бота.
> Для приватного каналу без @username вкажіть числовий id виду `-100…`.

### 4. Перевірте джерела
```bash
pip install -r requirements.txt
python -m bookbot check      # які стрічки працюють і скільки там новин
python -m bookbot preview    # як виглядатимуть пости (нічого не надсилає)
```

### 5. Запустіть

**Через Docker** (найпростіше на сервері):
```bash
docker compose up -d --build
docker compose logs -f       # подивитися журнал
```

**Без Docker** (Python 3.11+):
```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m bookbot
```

Бот працює через polling, тому публічна адреса чи домен не потрібні. Підійде будь-який VPS, домашній комп'ютер або Raspberry Pi.

## Команди (лише для адмінів)

| Команда | Що робить |
|---|---|
| `/status` | стан: черга, скільки опубліковано, чи є пауза, тихі години |
| `/sources` | список джерел зі статусом 🟢 / 🔴 і текстом помилки |
| `/add <адреса> [назва]` | додати джерело (можна адресу сайту — RSS знайдеться сам) |
| `/toggle <id>` | увімкнути або вимкнути джерело |
| `/remove <id>` | видалити джерело |
| `/fetch` | зібрати новини зараз |
| `/queue` | що буде опубліковано далі |
| `/review` | ще раз надіслати новини, що чекають модерації |
| `/post` | опублікувати наступний пост негайно (ігнорує паузу й тихі години) |
| `/pause`, `/resume` | призупинити або відновити публікації (збір триває) |

Звичайним користувачам бот лише вітається й радить підписатися на канал.

## Налаштування джерел — `sources.yaml`

```yaml
sources:
  - name: Читомо
    url: https://chytomo.com/feed/
    tags: ["#Читомо"]

  - name: Google Новини
    url: https://news.google.com/rss/search?q=книжкова+новинка+OR+"нова+книжка"&hl=uk&gl=UA&ceid=UA:uk
    include: [книж, книг, роман, видав]      # лише новини з цими словами
    exclude: [трудова книжка, книга скарг]   # і без цих
```

- Слова шукаються **як частина слова** без урахування регістру: `новинк` знайде «новинка», «новинки», «новинку».
- Більшість сайтів на WordPress мають стрічку за адресою `сайт/feed/`.
- Пошуковий запит Google Новин можна змінити (параметр `q=`), наприклад `q=фентезі+новинка` чи `q=Видавництво+Старого+Лева`.
- Після змін у файлі перезапустіть бота: `docker compose restart`.

> ⚠️ Адреси стрічок у `sources.yaml` я не зміг перевірити наживо. Перед запуском виконайте `python -m bookbot check`. Якщо якесь джерело не працює, бот покаже помилку, а решта джерел працюватимуть далі.

## Основні параметри `.env`

| Параметр | За замовчуванням | Опис |
|---|---|---|
| `MODERATION` | `false` | `true` — новини йдуть спершу адмінам на схвалення |
| `FETCH_INTERVAL_MIN` | `30` | як часто перевіряти джерела, хв |
| `POST_INTERVAL_MIN` | `20` | мінімальний проміжок між постами, хв |
| `QUIET_HOURS` | `23-8` | не публікувати в ці години (`off` — вимкнути) |
| `TIMEZONE` | `Europe/Kyiv` | часова зона для тихих годин і ліміту на добу |
| `MAX_POSTS_PER_DAY` | `0` | ліміт постів на добу (0 — без ліміту) |
| `MAX_AGE_DAYS` | `3` | новини, старші за стільки днів, не публікуються |
| `MAX_NEW_PER_SOURCE` | `5` | скільки нових новин брати з джерела за раз |
| `POST_SIGNATURE` | — | підпис під кожним постом, напр. `@my_books_channel` |

## Чому немає постів?

1. `/status` показує причину: пауза, тихі години або ліміт.
2. `/sources`: якщо джерело 🔴, під ним видно помилку.
3. `/queue`: якщо черга порожня, свіжих новин, що пройшли фільтри, поки немає. Спробуйте `/fetch`.
4. У журналі (`docker compose logs`) може бути «Не можу публікувати в канал». Це означає, що бот не адмін каналу або в нього немає права публікувати.

## Структура проєкту

```
bookbot/
  app.py        запуск бота, команди once / check / preview
  service.py    збір, черга, модерація, публікація
  feeds.py      завантаження й розбір RSS, пошук стрічки на сайті
  filters.py    ключові слова, хештеги, тихі години, дедуплікація
  formatter.py  оформлення поста з урахуванням лімітів Telegram
  handlers.py   команди адміна й кнопки модерації
  db.py         SQLite (data/bookbot.sqlite3)
sources.yaml    джерела й правила
.github/workflows/bookbot.yml   запуск на GitHub Actions
tests/          автотести:  pip install pytest pytest-asyncio && pytest
```
